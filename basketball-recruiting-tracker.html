International Basketball Recruiting Tracker

Project doc · started September 2026 · built with a friend

A weekly Claude-run pipeline that keeps tabs on international middle and high school basketball prospects for NCAA recruiting. It flags players who are standing out and compares their paths to international players who made it to the pros.

  • Status: Phase 1, finding sources
  • Cadence: weekly scheduled task
  • Output: hosted report + email

Overview

A friend of mine is really into college basketball, and that's turned into following the international youth players who could end up there. We wanted a way to track those prospects without doing all the digging by hand every week. It's also a good excuse for me to practice Claude's scheduled tasks, connectors, and web research on something real.

Each week the pipeline:

  • Checks known sources (and looks for new ones) for updates on a shortlist of prospects
  • Logs notes and stats, with names, sources, and context
  • Flags players who are playing up an age group or putting up numbers well above their level
  • Compares tracked players to international players who went pro, to spot anyone on a similar path
  • Posts a dated report and updated player histories to a simple website, then emails a link

Scope and phasing

Phase 1

Finding sources

Before the weekly tracking is worth much, we need a good list of where to look. The big sites (Rivals, 247Sports, MaxPreps and the like) are easy. The hard part is the regional and academy-specific sources where good players outside the big pipelines actually show up.

Phase 2

Weekly tracking

Once the source list is in good shape, the weekly run works through it: logging notes and stats, flagging standouts, and updating each player's history. Any new sources it finds along the way get added, so source discovery never really stops.

Where the first pass stops

Our guess is that very little real talent sits more than two steps away from the big, well-known programs. So the first pass starts from:

  1. The best-known academies around the world, and
  2. Current pro players, traced back through the academies, teams, and coaches they came up through

From each of those it goes exactly one step out (rival academies, teammates, and coaches who moved in or out) instead of trying to map the whole world at once.

How it finds players

The whole point is that good academies can be almost invisible in mainstream recruiting coverage. Maybe only two or three of their players ever ended up at a known school, so nobody's watching them. These methods overlap on purpose. For example, federation and tournament sources also get searched in local languages.

  • Working back from the pros

    There aren't that many international NBA players, so it's practical to trace each one back to the academy that produced them, then look at the rival academies in the same region. Strong competition is a good sign even if that academy hasn't produced a pro yet.

  • Tournament and federation data

    Youth national team rosters and continental tournament results often list players before recruiting sites pick them up, so we search those directly.

  • Following coaches

    When an assistant or youth coach moves from a small academy to a bigger program (or the other way), players often follow. So coaches get tracked too, especially ones who've developed several players who went on to strong programs. Where coaches got certified matters as well, since one country's coaching pipeline can lead to several unrelated academies.

  • Clinics and camps

    Showcases, combines, and continental youth championships are often the first time a small academy's players or coaches get in front of bigger programs and scouts, so we treat them as discovery events.

  • Searching in other languages

    A lot of the useful info for places like the Balkans, francophone Africa, and the Baltics just isn't in English, so we search in the local language.

Any new source found through any of these gets added to the list for future runs.

Keeping track of who's who

You can't match players week to week by name alone. Spellings change a lot when names get transliterated, and two different players can have the same name.

Matching players

  • Each player gets a permanent ID the first time they're found.
  • Later runs match on date of birth, nationality, current academy, and physical profile, not just the name.
  • If something's close but not an exact match, it gets flagged as "possible match, needs confirmation" for a person to check, instead of being merged or duplicated automatically.

Teams and academies

  • A player's team is tracked separately from who they are, with the full history kept. Switching teams gets logged as an update, not as a new player or a mismatch.
  • A player can be on more than one team at once (a club team and a national youth team, say) without looking like a new player.

How it runs

My friend isn't very technical, so this stays a Claude scheduled task instead of custom infrastructure. There's one shared task under one account, not a copy for each of us. My friend reads the weekly site and email, and sends names and notes through a simple intake that feeds into the next run.

  1. Weekly scheduled task fires
  2. Research the shortlist using the methods above
  3. Add any new sources to the list
  4. Match players: known, new, or unclear
  5. Write up notes, stats, and flags for each player
  6. Save a dated report and update each player's history
  7. Push to the website (GitHub Pages)
  8. Email a link to the new report

What it needs access to

  • A GitHub connector, to push the new report and player pages to a GitHub Pages site
  • Some way to send email (a connector or an API) for the weekly link
  • Web search, which Claude already has

The connectors need to be authorized once. Most of the setup work is that, plus writing task instructions detailed enough that Claude follows the matching and source-finding rules the same way every week. After that it should mostly run itself.

Repo layout

A repo holds the website plus the weekly task's data and prompt, so the scheduled task (or me in a Claude Code session) always knows where to read and write.

What the weekly instructions say

Roughly what /prompts/weekly_task.md tells the task to do each run:

  1. Load /data/players/*.json and /data/sources.json
  2. Run the search methods across the shortlist and one step out
  3. Try to match each finding to an existing player, and log unclear matches separately instead of guessing
  4. Record notes, stats, and flags for each matched or new player
  5. Add any new sources to /data/sources.json
  6. Write /data/reports/<date>.json and update the player files
  7. Run build_site.py, then commit and push through the GitHub connector
  8. Send the weekly email with a link to the new report

The weekly report and the player pages both come from the same data and get rebuilt every week, so nothing has to be updated by hand.
